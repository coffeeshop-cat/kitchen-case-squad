# 主厨与管家工作流

工作空间开通后，创建低代码工作流。用已有食材先验证「主厨出菜、管家核库存」，再接网页。

## 节点与变量

- 开始节点收一个字符串参数 `case_json`，内容为 `{"items":[{"id":"i1","name":"鸡蛋","qty":3,"unit":"个"},{"id":"i2","name":"番茄","qty":2,"unit":"个"}]}`。应用只发送确认可用的食材。
- 主厨读取 `case_json`，输出结构化 `proposal`。提示词可用「用清单里的食材拟一道家常菜。每项用料保留原编号和单位，填实际用量。油、盐、酱油可作为常备调味料。做法用普通中文短句。条件不足时返回 status=insufficient。」
- 管家读取原清单和主厨提案，输出 `audit`。提示词可用「逐项对照编号、单位、用量与库存。全部符合才给 pass，否则给 reject，并写清具体原因。保留主厨提交的配方供后续验证。」
- 结束节点把两份结果映射到同一个对象，输出为 `result_json`。以下是应用需要的业务结果，外层响应由控制台发布后的实际返回确定。

```json
{
  "proposal": {
    "status": "ready",
    "title": "番茄炒蛋",
    "duration_min": 12,
    "servings": 2,
    "used_items": [
      {"id": "i1", "qty": 2, "unit": "个"},
      {"id": "i2", "qty": 1, "unit": "个"}
    ],
    "steps": [
      {"title": "备料", "detail": "鸡蛋打散，番茄切块。", "minutes": 3},
      {"title": "炒蛋", "detail": "热锅下油，炒蛋后盛出。", "minutes": 3},
      {"title": "合炒", "detail": "炒软番茄，放回鸡蛋，加盐调味。", "minutes": 4}
    ]
  },
  "audit": {"status": "pass", "reason": "鸡蛋和番茄都够用。"}
}
```

## 发布与接入

调试完成后发布工作流，从「开发中心 > 智能体管理 > 工作流」复制完整的调用地址。请求是 `POST /runtimes/{runtime_name}/invocations`，使用 Bearer 凭证、会话标识与 `{"inputs":{"case_json":"..."}}` 请求体。[华为云工作流调用指南](https://support.huaweicloud.com/bestpractice-agentarts/agentarts_06_0022.html)

在启动后端的本机进程环境里设置 `MEAL_PLAN_PROVIDER=agentarts`、`AGENTARTS_WORKFLOW_URL` 与 `AGENTARTS_API_KEY`。API Key 留在本机启动环境，页面端只访问项目后端。先用发布端点核对 `result_json` 在实际低代码响应里的包装，再跑网页验收。

## 两组验收输入

1. 鸡蛋和番茄都可用。读回计划用量和会诊记录，确认库存扣减建议在数量范围内。
2. 将鸡蛋弃用，或把鸡蛋改成与库存单位不一致的提案。管家应给出明确原因，程序也会阻止超量、单位错配或使用弃用条目。

当前的验证使用本地替身响应。实际调用需要工作空间获准并完成发布。
